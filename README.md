# 实验编程 Vibe Coding 冲刺营｜2026年9月班作品库

这里记录每次课的创作成果、迭代过程和学习问题。每位学员每课提交一份作业，逐步积累自己的作品与开发记录。

## 从这里开始

1. 阅读 [提交规则](CONTRIBUTING.md)。
2. 查看 [第一课完整示例](submissions/example/lesson-01/README.md)。
3. Fork 本仓库到自己的 GitHub 账号，再 clone 到本地。
4. 从班级仓库最新默认分支创建本次作业分支。
5. 在 `submissions/你的GitHub用户名/lesson-01/` 放入成果。
6. commit、push 到自己的 Fork，向本仓库默认分支提交 PR。
7. 把 PR 链接发到课程群，等待老师查看与收录。

不要直接修改 `example` 示例目录，也不要修改其他学员的文件。

## 每次课提交什么

| 课次 | 成果重点 |
| --- | --- |
| 第1课 | 一件可运行的交互作品或小游戏 |
| 第2课 | 项目首版及 PROJECT、SPEC、DESIGN 文档 |
| 第3课 | 一次功能迭代、工作规则与交接记录 |
| 第4课 | 数据或 API 接入成果及实际完成情况 |
| 第5课 | 多智能体分工与合并后的成果 |
| 第6课 | 最终作品、访问链接与项目总结 |

具体任务以当堂要求为准。没有完全做完也可以提交，请如实记录当前进度与问题。

每份作业至少包含：**成果文件或项目链接、一张截图、一份简短 README**。

## 如何查看作品

进入学员对应课次目录查看 README 与截图。HTML 在 GitHub 文件页面显示的是源代码；下载作品和必要素材后，在浏览器打开 `index.html`。有在线体验链接时，可直接访问。

公开代码仓库不等于作品已经部署为网站。

## 反馈与收录

PR 是本次作业的提交和反馈入口。老师合并表示已收录，不代表所有功能均已完成或验收通过。

PR 未合并时，在同一分支继续修改并 push，原 PR 会更新。PR 已合并后，后续修订请从最新默认分支新建分支和 PR。

## 公开展示与署名

本仓库公开可见，请只提交愿意公开的内容。不适合公开的作品，通过课程群联系老师另行提交。

每份作业单独填写“可用于课程宣传：是／否”和署名。未明确同意时，不纳入课程宣传选集；不同意宣传不影响作业收录与反馈。

作品权利归相应创作者或权利人所有。仓库公开与作业提交本身，不代表授予他人任意使用、改编或商业使用的许可。引用素材请说明来源及适用许可；课程宣传使用前，仍需核对素材范围和署名。
